## Timing and compatibility

`account.notificationCreatedAt` records generated notification creation/first-seen times under role-and-ID keys. The authenticated response boundary writes missing timestamps once; preparing data for command validation does not mutate the ledger. Subsequent identical reads/polls do not rewrite it. Existing notification IDs and read markers are preserved.

Activity retains its original event timestamp. Existing generated updates without a ledger entry receive a first-seen time when first exposed after this update; the app cannot reconstruct an original event time that was never recorded. A changed suggestion score or genuinely new reminder identity receives a new timestamp. Session instants and date-only milestone deadlines do not become notification creation times. Deadline context retains UTC; sessions display their timezone; date groups use the viewer's local calendar day.

The first exposure of a new generated update may advance the workspace revision to persist its timestamp. The legacy migration check verifies revision preservation before login, then verifies that the source file remains unchanged after login. No database reset, external service or new package is required. Restart an already-running backend to load the timing changes and added public mentor context.

## Verification

- All 63 unit tests passed. Five new checks cover fit zero/missing/unavailable distinctions, calendar-day grouping and missing dates, accessible destination fallbacks, persisted match creation/read state, and session reminder timing. Existing reminder tests now verify stable timestamps through repeated reads and restart, separate UTC due time, and no revision change on unchanged reads.
- The full existing browser suite ran 76 scenarios across Chromium, Firefox, WebKit and the prototype project. Seventy passed immediately; six still expected the old collapsed history or Updates heading. Those assertions were updated to check the new visible history and unread status; all six passed on rerun across the three engines.
- After the final header Escape behavior change, six further fresh-workspace and keyboard/accessibility regression checks passed across all three engines.
- Playwright CLI checks exercised founder and mentor viewing/editing; draft survival through navigation and role changes; failed-save preservation and successful retry; validation and cancel; saved and outgoing introduction states; real mentor-facing incoming requests; decline, resend, acceptance and existing-room navigation; and unavailable profile recovery.
- Updates checks covered individual/bulk read actions, All/Unread filtering, refresh persistence, stable times, header consistency and Escape dismissal. Read-only response fixtures exercised 18 mixed updates, long prose, a long unbroken reference, Today/Yesterday/Earlier/missing-date groups and missing room/profile destinations. These fixtures were confined to the review browser and were not inserted into the working database.
- Actual zero, missing inputs and unavailable factor scores were checked visually and behaviorally, including the absence of bars for missing/unavailable data.
- Layouts were reviewed at 360, 390, 768 and 1440px, with no horizontal overflow. The mobile action panel follows the identity summary without overlaying it; the header preview fits inside the viewport and scrolls independently.
- Automated axe checks reported zero WCAG 2 A/AA and 2.1 AA violations on Match details, Profile and Updates in the review browser. Existing cross-browser checks also cover profile editing and keyboard navigation.
- Format check, production build and `git diff --check` passed.
