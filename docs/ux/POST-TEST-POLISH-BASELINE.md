## Style ownership and design rules

Styles load in this order: `styles.css`, `planning.css`, `discovery.css`, `match-overlays.css`, `shared-ui.css`, `profile-pages.css`, `mentorship.css`.

- `styles.css`: legacy shell, input, header and notification positioning, login layout. `shared-ui.css`: identity and shared controls/feedback; B adds the reusable interactive surface and SelectField here. `discovery.css`: match card composition. `match-overlays.css`: native-dialog layouts. `profile-pages.css`: full/compact Update rows, profile grouping and additional notification sizing. `planning.css` and `mentorship.css`: feature-specific layout.
- Keep B edits in these owners; avoid another global override stylesheet. C should consolidate notification sizing/positioning in one owner. E may reorganize legacy rules after regression checks.
- Spacing: 4/8/12/16/24/32px. Controls: minimum 44px height, 8px corners. Readability: preserve body sizes and allow labels/options to wrap. Shadows belong to floating surfaces.
- Hover: soft green surface and border on the whole parent control; no text-only response, pulsing or independently clickable info icon. Focus: independent 2px green ring with 3px offset. Forced colors keeps a system-color option outline.
- Dropdowns: focus stays on the combobox trigger with `aria-activedescendant`; `aria-selected` means committed value, highlight means pending choice. Escape cancels; Tab dismisses without trapping. Form validation/reset/change events must work through the native backing select. Custom panels use browser Popover top-layer positioning and remain descendants of their owning dialog when applicable.
- Layer ownership: legacy header 4, sidebar 5, mobile navigation 25, ordinary popover token 30, toasts 40, overlays/native dialogs in the browser top layer. A select popover opens in that top layer after its owning dialog, so a higher CSS z-index alone is not the solution. This records existing layers; it does not claim to consolidate legacy z-index values.
- Position menus from actual trigger/visual-viewport bounds; clamp horizontally, open upward if needed, bound list height, reposition on scroll/resize. No document-wide overflow clipping.
- Motion: 120ms tint/border/shadow transitions; disable under reduced motion. C's notification animation should follow the same rule. Background decoration stays static and ignores pointer input.
