## Operating details

- The early theme initializer is a same-origin script, compatible with the built server's script CSP. Preference is browser-local, independent of account/role. Storage failures leave the current visit usable.
- Photo previews are reduced locally for practical tab-draft storage; the server independently decodes and re-encodes images using [Sharp](https://sharp.pixelplumbing.com/api-constructor/), rejects animated or over-40-megapixel server inputs, and strips metadata. Saved photos use owned `/api/avatars/:id` references. Authenticated image fetches permit the owner, an eligible viewer or an existing collaborator. Replaced/removed references stop being served. Original file infrastructure quotas and backups still apply. Unreferenced old files remain in storage; no data-pruning job was added.
- A prototype room created through simulated introduction acceptance still waits for the fictional partner on subsequent mutual steps. Use two local password accounts for a full reciprocal demonstration.
- Reports use the existing local moderator queue. A configured moderator must review them; no external reporting service or email is introduced.
- Server restarts still end sessions, while stored profiles, rooms, files, reports and notification read state remain persistent. Per-tab unpublished drafts follow the existing session-storage model and are cleared only on successful voluntary sign-out or explicit Cancel.
