The custom control preserves a native select for successful-control FormData serialization, required validation and reset. Custom commits dispatch normal bubbling input/change events so form-level draft handling can observe them. Invalid input focuses the visible trigger and supplies an error description. Controlled consumers receive the native change event; uncontrolled consumers restore the native default after reset. A browser test found that reset microtasks can precede the default reset action; the component reads back in the next task instead. Safari pointer activation explicitly focuses the trigger before opening so keyboard navigation consistently targets the current control.

The options panel uses the browser's Popover top layer. It is portaled into the owning dialog when present, rather than leaving options outside the dialog's interactive subtree. Enter/Space opens and commits, arrows/Home/End highlight enabled options, type-ahead finds labels, Escape cancels, Tab leaves normally, and outside pointer activation dismisses. The panel repositions on viewport/scroll/resize, accounts for CSS zoom, and opens above a trigger near the bottom edge. Browser zoom/reflow and native validation do not rely on a hidden input alone.

## Verification

- Initial baseline: 69 unit tests, format check and production build passed.
- The full browser suite ran 89 scenarios: 86 passed initially. Two mentor journeys timed out in the existing layout helper after a transient toast expired between its visibility check and dismissal. The helper now bounds that click and ignores the failure only when the toast has disappeared; a still-visible undismissable toast still fails. Both affected journeys passed on rerun in Firefox/WebKit. A prototype scenario retained the old help accessible name during the implementation run; both prototype scenarios passed after updating the locator to the final native disclosure label.
- Existing prototype coverage now operates the visible custom sort instead of `selectOption`, checks fit/name/experience choices, keyboard cancel/commit/type-ahead, Tab dismissal, pagination/filter behavior, and explanation-dialog focus return.
- The separate CLI harness passed in Chromium, Firefox and WebKit: required validation/error focus, disabled-option skipping, FormData, bubbling form change, defaults/reset, controlled updates, Escape cancellation, Tab and outside dismissal, empty/disabled states, modal selection, long options, active-option scrolling and upward viewport placement at 1440, 1024, 768, 390 and 360px.
- A mobile touch context selected multiple sort options successfully. The real Matches page passed reduced-motion, forced-colors, viewport bounds and no-horizontal-overflow checks. An Axe WCAG A/AA check with the custom listbox open reported no violations. This verifies accessible markup and keyboard behavior; a manual screen-reader session was not performed.
- Matching screenshots and scripts are local ignored artifacts in `output/playwright/polish-ab/`. Additional unchanged Updates baseline fixtures cover 0, 1, 6 and 24 mixed-read updates, long text and session/deadline metadata at desktop/mobile widths. Those fixtures were injected into browser responses only, without writing invented activity to the database.

Final verification passed: all 69 unit tests, repository formatting, production build and `git diff --check`. All 89 distinct browser scenarios passed across the full run and focused reruns described above; the suite was not rerun wholesale after resolving its transient-toast race and final help locator. The final custom-sort scenarios were rerun after the placement changes. A [200% CSS layout-scaling check](../../output/playwright/polish-ab/after-sort-200-percent.png) confirmed bounded popup placement and readable wrapping, followed by a real Match details navigation check retaining its header context. This is a CSS scaling/reflow check, not a claim that a particular browser's zoom shortcut or screen reader was manually exercised.
